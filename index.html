Assigns HS/HTS customs codes to every product in a cross-border Shopify merchant's catalogue, cites the legal basis (GRI & Chapter Notes), and calculates Section 301 tariffs & total landed cost. Instead of blind LLM guessing, every classification is gated by a three-tier confidence protocol:

Stopping the Infinite Rerun Loop

终结无限重跑死循环与 Token 爆炸

Early peer agents had no definition of "good enough"—they looped endlessly over 0.001% rounding differences, burning my token budget. I refactored the system into 1 Leader + Parallel Workers with explicit error tolerances and 150-char summary handoffs.

在冲突回测中区分真实信号与过拟合

A rule that shines in 1997–2011 often fails in 2012–2025 or crashes in 1934–1985. Rather than curve-fitting until backtests look pretty, our current work focuses on statistical gates that reject false positives across regimes.

在 1997–2011 开发段表现优异的规则，往往在 2012–2025 留出段反转，或在 1934–1985 极端行情中崩溃。我们拒绝拼凑好看的曲线，重点用严苛的统计门禁剔除跨周期假阳性。

Before: Unbounded Peer-to-Peer Review Loop

重构前：无边界平级互审与重跑死循环

Early Bottleneck 早期瓶颈
  • No "Good Enough" Threshold: When the Review Agent recomputed metrics using a slightly different float reduction order or fee rounding ($0.01 difference on a single trade row), it flagged a mismatch and forced the Backtest Agent to re-run from scratch.
  • Quadratic Context Bloat: Agents passed entire raw conversation histories and multi-page stdout logs across sessions (43,493 tokens on turn 1 growing to 237,930 tokens by turn 8 in client logs).
  • Zero Fault Isolation: A single missing ticker date or unverified data column blocked the entire chain while agents debated how to patch policy on the fly.
  • 缺乏“什么叫够好”的标准： 复核 Agent 只要算出一丝浮点累加顺序差异或单行 $0.01 的手续费四舍五入尾差，就会判定不一致并打回重跑，陷入无休止的复核死循环。
  • 上下文平方级膨胀： 跨轮次直接传递完整聊天记录与长篇终端日志（实测客户端日志第 1 轮输入 43,493 tokens，到第 8 轮暴涨至 237,930 tokens）。
  • 缺乏故障隔离： 任何单个日期缺口或字段歧义都会阻塞整条流水线，多个 Agent 在对话里反复拉锯补丁方案。

After: 1 Leader + Parallel Workers + Tolerance Gate

重构后：1 组长 + 并行工作槽位 + 误差容忍度门禁

Current Production Workflow 现行生产工作流
  • 1 Leader + Parallel Slot Queues: The Leader Agent (leader.py) writes self-contained task contracts (≤4,500B) with pre-computed positive/negative test fixtures (g5-pos.json / g5-neg.json). Workers claim tasks atomically from isolated queues without touching each other's directories.
  • Explicit Error Tolerances (Decision 39): Metric reproduction within ±0.05 pp, single-row fee rounding ≤$0.01 (≤$0.05 batch), and metric floats within 1e-6 relative (task-card contracts tighten series checks to rtol=1e-9, atol=1e-12) pass automatically, provided trade direction, constituents, share rounding, cash attribution and gate verdicts are unchanged—minor diffs below threshold are logged as notes, never re-run.
  • Short Summary Handoffs (handoff_meta.py): Workers output a strict 5-field DONE.md (≤150 char conclusion + single literal re-check command) and an automated DONE.meta.json sidecar. The Leader reads compact brief.py delta packets (≤4,000 chars) and rotates sessions every 3–5 turns.
  • 1 组长 + 并行槽位队列： 组长 Agent（leader.py）派发自包含任务合同（≤4,500B）与预计算的已知答案正/负夹具（g5-pos.json / g5-neg.json）。各 Worker 从各自槽位原子认领、隔离写入，互不踩踏。
  • 明确误差容忍度（决定 39）： 异路径复算核心指标容差 ±0.05 个百分点、参考费用舍入单行 ≤$0.01（整批 ≤$0.05）、指标浮点相对误差 1e-6（各任务卡合同对序列另定更严的 rtol=1e-9, atol=1e-12）；只要不改变交易方向、名单、整股取整、资金归属与门槛判定，微小尾差只记日志备查，不再重跑。
  • 结构化短摘要交接（handoff_meta.py）： Worker 结束时只交 5 项 DONE.md（结论 ≤150 字 + 单条复算命令）并自动生成 DONE.meta.json；组长每轮只读 brief.py 差量包（≤4,000 字符）并按 3–5 轮周期换新会话。

How Cross-Session Memory Handoffs Work

跨会话短摘要交接机制是如何运作的

Instead of feeding a 200k-token chat transcript into the next agent session, every Worker session terminates by writing a 5-field DONE.md card (Result, One-Line Conclusion ≤150 chars, Output Files, Single Re-Check Command, Blocker/Next).

我们不再把长达 20 万 Token 的聊天记录塞给下一个会话，而是强制每个 Worker 结束时只写一张 5 项 DONE.md 交接卡（结果、一句话结论 ≤150 字、产出文件、单条复算命令、下一步/阻塞）。

When board.py --finish runs, handoff_meta.py scans file modification timestamps inside the claim window, verifies that no protected files (SESSION-RULES.md, STRATEGY-REGISTRY.md, _leader/) were touched, executes the single re-check command, and emits DONE.meta.json.

当执行 board.py --finish 时，handoff_meta.py 会自动扫描认领时间窗内的文件修改时间，硬拦截任何偷改受保护文件（如 SESSION-RULES.md、登记簿、_组长/）的行为，实测复算命令退出码，并自动生成 DONE.meta.json 供组长秒级预审。

Stopping Rerun Loops via Explicit Error Tolerances

用明确的误差容忍度终结无限重跑死循环

In Decision 39 and each task card's contract, we codified exact numerical tolerances for every check layer. If an independent verification run lands inside the tolerance band and preserves trade direction, constituent rankings, and gate verdicts, the discrepancy is logged as a non-blocking audit note and the task is closed immediately.

在 决定 39 与各任务卡合同中，我们为每一层核验明确规定了数值容差上限。只要异路径复算结果落在容差带内，且不改变交易方向、选股名单、整股取整与门槛判定，微小尾差直接记入审计日志并收口结案，严禁反复重跑。

  • Account Metrics (G3 Gate): ±0.05 percentage points (0.0005) on annualized CAGR, Daily MaxDD, and Calmar ratio.
  • Reference Cost & Fee Rounding: Single-row rounding diff ≤ $0.01 and batch sum diff ≤ $0.05 are logged and halted—never re-run.
  • Float Array & Prefix Invariance: rtol = 1e-9, atol = 1e-12 on daily return arrays; ≤ 1e-12 max difference on pre-cutoff NAVs when future data is perturbed.
  • Model Fitting Budget (fit_counter.py): Hooks numpy.linalg.lstsq/solve and model .fit() entry points so a study cannot silently run 50 regressions while claiming a single test.
  • 账户级核心指标（G3 门槛）： 年化 CAGR、日最大回撤 MaxDD、Calmar 比率统一采用 ±0.05 个百分点（0.0005）容差。
  • 参考交易成本舍入： 单行舍入差 ≤ $0.01 且整批绝对差合计 ≤ $0.05 直接列注停修，不触发重跑。
  • 浮点序列与无前视前缀不变性： 逐日收益序列比对采用 rtol = 1e-9, atol = 1e-12；对未来数据施加正余弦扰动后，截断日前净值最大差须 ≤ 1e-12。
  • 模型拟合次数硬上限（fit_counter.py）： 在脚本入口挂载计数守卫，防止 Agent 表面宣称单次测试、实则在循环里偷偷拟合数十次参数。

# 1. Tolerance constants (Decision 39: pp / USD / 1e-6 metrics; series rtol/atol from task-card contracts)
METRIC_TOLERANCE_PP = 0.05          # ±0.05 percentage points on CAGR / MaxDD / Calmar
COST_ROW_ROUNDING_TOL_USD = 0.01    # ≤$0.01 single-row rounding: log note, do NOT rerun
COST_BATCH_ROUNDING_TOL_USD = 0.05  # ≤$0.05 full-batch sum diff: log note, do NOT rerun
ARRAY_RTOL = 1e-9                   # Relative float tolerance for daily return series
ARRAY_ATOL = 1e-12                  # Absolute float tolerance & prefix invariance bound

def verify_metric_within_tolerance(expected_pp: float, actual_pp: float,
                                   direction_changed: bool) -> dict:
    diff_pp = abs(actual_pp - expected_pp)
    if direction_changed:
        return {"status": "REJECT_RERUN", "reason": "signal_or_verdict_flipped"}
    if diff_pp <= METRIC_TOLERANCE_PP:
        return {
            "status": "PASS_LOG_ONLY",  # Halts infinite review loop
            "abs_diff_pp": round(diff_pp, 8),
            "action": "record_audit_note_no_rerun"
        }
    return {"status": "FAIL_G3_GATE", "abs_diff_pp": round(diff_pp, 8)}

Single-Task Execution & Portable Verification Log

单次真实回测任务执行与正负夹具核验流水

Every study card defines a Positive Fixture (P1), a Negative Deliberate-Fault Fixture (N1), a Historical Anchor & Prefix Invariance Test (P2), and an Independent Full Re-Check (P3).

每张研究任务卡在派单前均由组长锁定四道机器判据：正例已知答案小样（P1）、负例故意破坏夹具（N1）、历史锚点与截断前缀不变性（P2）以及全量独立复算（P3）。

Why require a Negative Fixture (N1)? Early on, a Worker Agent accidentally wrote a check.py script that imported the production script's summary variables and always printed PASS. Requiring check.py --fixture g5-neg.json to exit with rc=2 on an injected lookahead error (signal_lag_days=0) guarantees the checker actually validates the math.

为什么要强制跑负例夹具（N1）？早期曾有 Worker 写的 check.py 直接 import 了生产脚本算好的变量自证，导致“无论数据怎么错都永远打印 PASS”。强制要求 check.py 对注入了同日成交前视错误（signal_lag_days=0）的 g5-neg.json 返回非零退出码 rc=2，彻底杜绝了“检查器与实现同源假通过”。

Section 04 · Empirical Reality & Statistical Discipline 第 04 节 · 真实回测案例与过拟合难题

Sample Backtests & The Overfitting Puzzle 真实回测案例：当不同时间窗口给出冲突结论时，如何剔除过拟合

Why we refuse to claim "market-beating alpha": in quantitative equity research, it is easy to find rules that look extraordinary in a single 15-year window. The real engineering problem is building statistical gates that catch regime-specific overfitting when results conflict across time windows.

为什么我们绝不宣称“已找到稳赢市场的圣杯”：在量化研究里，在单一 15 年窗口里凑出一条漂亮曲线极其容易；真正的硬核工程问题，是当同一策略在开发段、留出段和长历史压力段给出冲突结果时，如何用统计检验与制度门禁把过拟合筛掉。

Case Study 01 · Cross-Window Reversal 案例 01 · 跨时间窗口反转 Final Verdict: Rejected (No Edge) 最终裁定：不胜出 (驳回)

S&P 500 Downside-Beta Penalized Momentum (2026-10-20)

标普 500 下行 Beta 惩罚动量选股 (2026-10-20)

Hypothesis: Rank S&P 500 constituents over 126 trading days by penalizing downside beta (Score = R_126 / (1 + max(beta_down, 0)), top 5 stocks, ≤2 per SIC industry, 6 staggered tranches, 15 bps cost). Screened by Agent G3-1019a; verified on holdout by isolated Agent G2-1020g.

策略机制： 在 126 日动量排序中对市场下跌日的下行 Beta 施加惩罚（Score = R_126 / (1 + max(beta_down, 0))，选前 5 只、单 SIC 行业 ≤2 只、六分仓轮动、单边成本 15 bps）。由会话 G3-1019a 筛查，隔离会话 G2-1020g 执行留出段正式核验。

复盘诊断： 惩罚下行 Beta 在包含互联网泡沫破裂（2000–02）与次贷危机（2008）的 1997–2011 开发段起到了防守缓冲作用，但在 2012–2025 科技与半导体领涨的结构性牛市中，系统性过滤掉了高弹性领涨股（2019–2025 单风险仓年化落后达 9.80 个百分点）。若无留出段与分段一致性硬门禁，该策略极易被误采纳。

Case Study 02 · Secular Crash Stress Gate 案例 02 · 跨世纪极端回撤与零拟合门禁 Final Verdict: Eliminated (M1 DD > 55%) 最终裁定：淘汰 (M1 回撤超 55%)

Sleeve Ratio V2 40/40/10/10 (2026-10-15) & Variance-Drain (2026-11-07)

仓比方案 V2 40/40/10/10 (2026-10-15) 与方差漏损对冲 (2026-11-07)

Hypothesis: Shift account sleeve weights from 30% Risk / 20% QLD / 40% Core / 10% Cash to 40% Risk / 40% QLD / 10% Core / 10% Cash (V2), and separately test a fit=0 2:1 short-QLD / long-2xNDX variance-drain overlay during high volatility (RV20 >= 0.28).

策略机制： 测试将四仓目标权重从 30/20/40/10 调整为 40% 风险 / 40% QLD / 10% 核心 / 10% 备用金（V2），以及零统计拟合（fit=0）在高波熊市期（RV20 >= 0.28）按 2:1 做空 QLD / 做多 2xNDX 收割复利方差漏损。

复盘诊断： 即便候选方案（V2 40/40/10/10）在开发段和 2012–2026 留出段双双跑赢基线（留出年化高 +3.66pp），252 日分块自助法（p = 0.620 < 0.70）与 1934–1985 M1 压力测试（1937–42 回撤达 -57.04% 破 -55% 红线）依然识别出该超额来自尾部杠杆暴露而非稳健 Alpha，予以否决。

How Our Multi-Agent Workflow Separates Signal from Overfitting (The 6-Gate Funnel)

多智能体系统如何区分真实统计信号与过拟合（六道防过拟合漏斗）

Every research card in strategy-vault is scored on execution rigor (G1–G6), never on whether the backtest return is positive (SESSION-RULES 3b). Negative results earn full credit so agents have zero incentive to p-hack.

在 strategy-vault 中，所有 Worker 会话只按证据与规范（G1–G6）计分，负结论与胜出同等计分（SESSION-RULES 3b），从机制上消除 Agent 为了“迎合正收益”而改参数凑数的动机。

1. Pre-Registration & Fit Cap (fit_counter.py) 1. 预先登记哈希与拟合计数上限 (fit_counter.py) study.json SHA-256 is locked before running numbers. fit_counter.py enforces fit_count <= N (often fit=0) at runtime. 跑数前先锁定 study.json 的 SHA-256；运行时由 fit_counter.py 硬卡模型拟合次数上限（多数机制检验强制 fit=0）。
2. Strict 3-Regime Isolation 2. 三大历史样本段物理隔离 Development screening (1997–2011, max 3 variants) is physically truncated from Out-of-Sample Holdout (2012–2026) and Pre-Sample M1 (1934–1985). 开发段筛查（1997–2011，最多 3 个变体）在字符串读取层物理截断，严禁触碰留出段（2012–2026）与预样本段 M1 (1934–1985)。
3. Crash-Year & Exposure-Matched Ablation 3. 危机年份剔除与同平均敞口对照 (k*B) Defensive timing rules must beat an equal-average-exposure baseline (k * B + (1-k) * Cash) even after removing 2000–02 and 2008. 防守择时规则在剔除 2000–02 与 2008 股灾年后，年化仍不得低于同日均股票敞口的固定比例基线（k*B）。
4. Friction, Borrow & delay1 Lag Stress 4. 双倍成本、借券费与 delay1 晚一天成交压力 All candidates are tested at 15 bps and 30 bps (2x cost), 100 bps/yr short borrow fees, and next-open (delay1) signal execution. 凡报改善必须同时报告 15 bps / 30 bps（2 倍成本）、做空借券费及信号次日开盘/晚一天（delay1）口径。
5. Holdout Wear Penalty (p >= 1 - 0.30/N) 5. 留出段磨损惩罚公式 (p >= 1 - 0.30/N) Each formal holdout test increments N (Decision 53). Six formal tests have been run, so the next one is N = 7 and block-bootstrap win probability must reach p >= 0.957 (1 − 0.30/N) to prevent multiple-testing decay. 留出段每正式检验一次累计次数 N 加 1（决定 53）；已正式检验 6 次，下一次 N = 7，自助法胜出概率门槛升至 p >= 0.957（1 − 0.30/N），防止多重检验磨损。
6. 12-Month Forward Shadow Ledger (shadow.py) 6. 12 个月前推影子账本并行验证 (shadow.py) Candidates passing statistical gates must run side-by-side in our daily paper-trading shadow ledger for 12 months before replacing baseline rules. 通过统计门禁的初步胜出候选，仍须在每日影子账本中与现行规则同段并行记账满 12 个月非劣后方可正式采纳。

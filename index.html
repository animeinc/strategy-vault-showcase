Phase 01 · Why I Started It

Eliminating Emotional Trading

When I began trading U.S. equities in early 2026, my worst drawdowns came from emotional reactions—chasing breakouts late and selling into short-term panic. I set out to codify a strictly rule-based daily strategy researched and audited by AI agents.

Phase 02 · What Broke & How I Fixed It

Stopping the Infinite Rerun Loop

Early peer agents had no definition of "good enough"—they looped endlessly over `0.001%` rounding differences, burning my token budget. I refactored the system into 1 Leader + Parallel Workers with explicit error tolerances and 150-char summary handoffs.

Phase 03 · Where It Stands Today

Signal vs. Overfitting in Testing

A rule that shines in `1997–2011` often fails in `2012–2025` or crashes in `1934–1985`. Rather than curve-fitting until backtests look pretty, our current work focuses on statistical gates that reject false positives across regimes.

Before: Unbounded Peer-to-Peer Review Loop

Early Bottleneck
  • No "Good Enough" Threshold: When the Review Agent recomputed metrics using a slightly different float reduction order or fee rounding (`$0.01` difference on a single trade row), it flagged a mismatch and forced the Backtest Agent to re-run from scratch.
  • Quadratic Context Bloat: Agents passed entire raw conversation histories and multi-page stdout logs across sessions (`43,493` tokens on turn 1 growing to `237,930` tokens by turn 8 in client logs).
  • Zero Fault Isolation: A single missing ticker date or unverified data column blocked the entire chain while agents debated how to patch policy on the fly.

After: 1 Leader + Parallel Workers + Tolerance Gate

Current Production Workflow
  • 1 Leader + Parallel Slot Queues: The Leader Agent (`leader.py`) writes self-contained task contracts (`≤4,500B`) with pre-computed positive/negative test fixtures (`g5-pos.json` / `g5-neg.json`). Workers claim tasks atomically from isolated queues without touching each other's directories.
  • Explicit Error Tolerances (`Decision 39`): Metric reproduction within `±0.05 pp`, single-row fee rounding `≤$0.01` (`≤$0.05` batch), and float arrays within `rtol=1e-9, atol=1e-12` pass automatically—minor diffs below threshold are logged as notes, never re-run.
  • Short Summary Handoffs (`handoff_meta.py`): Workers output a strict 5-field `DONE.md` (`≤150` char conclusion + single literal re-check command) and an automated `DONE.meta.json` sidecar. The Leader reads compact `brief.py` delta packets (`≤4,000` chars) and rotates sessions every 3–5 turns.

Stopping Rerun Loops via Explicit Error Tolerances

In `Decision 39` and `scoring_gate.py`, we codified exact numerical tolerances for every check layer. If an independent verification run lands inside the tolerance band and preserves trade direction, constituent rankings, and gate verdicts, the discrepancy is logged as a non-blocking audit note and the task is closed immediately.

  • Account Metrics (`G3` Gate): `±0.05` percentage points (`0.0005`) on annualized CAGR, Daily MaxDD, and Calmar ratio.
  • Reference Cost & Fee Rounding: Single-row rounding diff `≤ $0.01` and batch sum diff `≤ $0.05` are logged and halted—never re-run.
  • Float Array & Prefix Invariance: `rtol = 1e-9, atol = 1e-12` on daily return arrays; `≤ 1e-12` max difference on pre-cutoff NAVs when future data is perturbed.
  • Model Fitting Budget (`fit_counter.py`): Hooks `numpy.linalg.lstsq/solve` and model `.fit()` entry points so a study cannot silently run 50 regressions while claiming a single test.

# 1. Explicit Error Tolerance Constants (Decision 39 & Gate G3)
METRIC_TOLERANCE_PP = 0.05          # ±0.05 percentage points on CAGR / MaxDD / Calmar
COST_ROW_ROUNDING_TOL_USD = 0.01    # ≤$0.01 single-row rounding: log note, do NOT rerun
COST_BATCH_ROUNDING_TOL_USD = 0.05  # ≤$0.05 full-batch sum diff: log note, do NOT rerun
ARRAY_RTOL = 1e-9                   # Relative float tolerance for daily return series
ARRAY_ATOL = 1e-12                  # Absolute float tolerance & prefix invariance bound

def verify_metric_within_tolerance(expected_pp: float, actual_pp: float,
                                   direction_changed: bool) -> dict:
    diff_pp = abs(actual_pp - expected_pp)
    if direction_changed:
        return {"status": "REJECT_RERUN", "reason": "signal_or_verdict_flipped"}
    if diff_pp <= METRIC_TOLERANCE_PP:
        return {
            "status": "PASS_LOG_ONLY",  # Halts infinite review loop
            "abs_diff_pp": round(diff_pp, 8),
            "action": "record_audit_note_no_rerun"
        }
    return {"status": "FAIL_G3_GATE", "abs_diff_pp": round(diff_pp, 8)}

Section 04 · Empirical Reality & Statistical Discipline

Sample Backtests & The Overfitting Puzzle

Why we refuse to claim "market-beating alpha": in quantitative equity research, it is easy to find rules that look extraordinary in a single 15-year window. The real engineering problem is building statistical gates that catch regime-specific overfitting when results conflict across time windows.

Case Study 01 · Cross-Window Reversal Final Verdict: Rejected (No Edge)

S&P 500 Downside-Beta Penalized Momentum (`2026-10-20`)

Hypothesis: Rank S&P 500 constituents over 126 trading days by penalizing downside beta (`Score = R_126 / (1 + max(beta_down, 0))`, top 5 stocks, ≤2 per SIC industry, 6 staggered tranches, 15 bps cost). Screened by Agent `G3-1019a`; verified on holdout by isolated Agent `G2-1020g`.

Without strict out-of-sample holdout & sub-window consistency gates, this rule would have been mistakenly deployed.

How Our Multi-Agent Workflow Separates Signal from Overfitting (The 6-Gate Funnel)

Every research card in `strategy-vault` is scored on execution rigor (`G1–G6`), never on whether the backtest return is positive (`SESSION-RULES 3b`). Negative results earn full credit so agents have zero incentive to p-hack.

1. Pre-Registration & Fit Cap (`fit_counter.py`) `study.json` SHA-256 is locked before running numbers. `fit_counter.py` enforces `fit_count <= N` (often `fit=0`) at runtime.
2. Strict 3-Regime Isolation Development screening (`1997–2011`, max 3 variants) is physically truncated from Out-of-Sample Holdout (`2012–2026`) and Pre-Sample `M1 (1934–1985)`.
3. Crash-Year & Exposure-Matched Ablation Defensive timing rules must beat an equal-average-exposure baseline (`k * B + (1-k) * Cash`) even after removing `2000–02` and `2008`.
4. Friction, Borrow & `delay1` Lag Stress All candidates are tested at `15 bps` and `30 bps` (2x cost), `100 bps/yr` short borrow fees, and next-open (`delay1`) signal execution.
5. Holdout Wear Penalty (`p >= 1 - 0.30/N`) Each formal holdout test increments $N$ (`Decision 53`). At $N=5$, block-bootstrap win probability must reach `p >= 0.94` to prevent multiple-testing decay.
6. 12-Month Forward Shadow Ledger (`shadow.py`) Candidates passing statistical gates must run side-by-side in our daily paper-trading shadow ledger for 12 months before replacing baseline rules.
